# Tech Aim 0.9.0-RC1 — field-test plan

**FIELD TEST — NOT FOR OFFICIAL COMPETITION RESULTS**

The plan for controlled live testing against real Tech Aim / SETA hardware.
**Nothing in this plan has been performed.** Every result is recorded on
`0.9.0-rc1-field-test-checklist.md` on the day, by the operator.

---

## Objective

Prove, on real hardware, that the field-test build delivers:

- reliable target communication
- reliable shot capture
- reliable session storage
- reliable crash and power-loss recovery
- practical Windows deployment
- useful diagnostics when something fails

Everything else — analysis wording, Training Lab content, reports — is
secondary in this test.

## Environment to record before starting

Target model · electronic board version · firmware version · target serial
number · connection type · COM port or network path · protocol configuration ·
power supply · Windows computer and version · discipline · target distance ·
software version · Git commit · build date · operating mode · analytics
version.

The last five come from **Settings → ABOUT / BUILD**.

---

## A. Startup and connection

1. Start the application **with** the target connected.
2. Start the application **without** the target connected.
3. Connect the target **after** startup.
4. Start a session.

A clear, non-technical error is expected in case 2 — not a silent failure and
not a crash.

## B. Shot capture

5. Fire a sighter. 6. Confirm it appears **once**.
7. Fire a counted shot. 8. Confirm it appears **once**.
9. Verify the score. 10. Verify the decimal score where applicable.
11. Verify the X coordinate. 12. Verify the Y coordinate.
13. Verify the timestamp. 14. Verify the shot sequence.

## C. Communication loss and recovery

15. Disconnect the target. 16. Confirm a **clear** communication error.
17. Reconnect. 18. Continue the **same** session.
19. Confirm **no duplicate** shots. 20. Confirm **no missing** shots.
21. Complete the session.
22. Start another session **without restarting** the application.

## D. Recovery

R1 record several shots · R2 close normally · R3 unfinished session detected ·
R4 recover · R5 all shots unchanged · R6 record another shot ·
**R7 force-terminate `TechAim.exe`** · R8 restart · R9 recover again ·
R10 no duplicate · R11 no missing · R12 sequence continues · R13 complete ·
R14 restart · R15 the completed session is **not** offered as unfinished.

Where safe, also test a Windows restart mid-session.

> **Never interrupt target power while a projectile is being fired.**

## E. Data integrity — every shot

Compare, per shot: target-reported score · displayed score · stored score ·
target-reported coordinates · displayed coordinates · stored coordinates ·
shot type · position · sequence number · timestamp · wind snapshot where Wind
Map is in use.

**Any mismatch is Severity 1.**

---

## Severity

**Severity 1 — release blocking.** Wrong score · lost shot · duplicated shot ·
corrupted journal · recovery failure · target cannot connect · repeated crash
in normal operation · one athlete's session data appearing in another ·
completed session reopening as active · package cannot launch on a clean
machine.

**Severity 2.** Major workflow unusable · important analysis missing ·
confusing state with a safe workaround · support bundle fails · communication
recovery requires an application restart.

**Severity 3.** Visual alignment · minor wording · non-critical display ·
cosmetic inconsistency.

**Any open Severity 1 means NO-GO for weekend live deployment.**

## When something goes wrong

1. Note the time and what was happening.
2. Screenshot if the screen shows it.
3. Run `Make-SupportBundle.ps1 -SessionId <id>`.
4. Record the bundle name on the checklist.
5. Decide whether to continue or roll back
   (`0.9.0-rc1-rollback.md`).

---

## Out of scope for this test

- Wind Map PDF — not implemented; the button is inert.
- Formal coach review of Training Lab thresholds — separate process, does not
  block the field test.
- Official competition use — this build is not approved for it.
