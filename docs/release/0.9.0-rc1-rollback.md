# Tech Aim 0.9.0-RC1 — rollback

**FIELD TEST — NOT FOR OFFICIAL COMPETITION RESULTS**

How to stop using RC1 and return the range to ordinary operation **without
destroying any test evidence**.

---

## Before anything else

**The rollback must not delete RC1 test evidence.** Logs, journals, support
bundles and checklists are the reason the field test exists. Preserve first,
then roll back.

---

## 1. Stop RC1

1. Complete or abandon the current session through the application.
2. Close the application normally. If it will not close, note that fact on the
   checklist — a forced kill is itself a finding — then end `TechAim.exe` from
   Task Manager.

## 2. Preserve the evidence

**Do this before restoring anything.**

```bash
powershell -File Make-SupportBundle.ps1 -SessionId <affected session id>
```

Then copy the whole AppData tree aside:

| Preserve | From |
|---|---|
| Sessions and recovery journals | `%LOCALAPPDATA%\TechAim\Sessions` |
| Logs | `%LOCALAPPDATA%\TechAim\Logs` |
| Support bundles | `%LOCALAPPDATA%\TechAim\SupportBundles` |
| Exports and reports | `%LOCALAPPDATA%\TechAim\Exports`, `\Reports` |

Copy them to a dated folder, for example
`TechAim-RC1-evidence-2026-07-30\`, on a drive that is not being rolled back.
**Copy — do not move.** A move leaves the recovery store inconsistent if the
range is still live.

Also keep: the completed printed checklist, any screenshots, and the ZIP's
`.sha256` file so the exact package under test can be identified later.

## 3. Restore the previous build

The previous known-working development build is preserved separately at:

```
dist/previous/TechAim-previous-known-working/
```

RC1 **never overwrites it** — the packaging script writes only to
`dist/TechAim-0.9.0-RC1-FieldTest-Windows-x64`.

1. Extract or open the previous build folder.
2. Start its `TechAim.exe`.
3. Confirm the banner under **Settings → ABOUT / BUILD** shows the previous
   version and commit, **not** `0.9.0-RC1`.

## 4. Restore the previous configuration

The previous build carries its own `config.ini`. If it was changed for the
field test, restore:

```
app_mode=Live
developer_mode=0
is_single_decimal=1
```

There is no language key; English is the default.

**Do not copy RC1's `config.ini` into the previous build** — settings can
change between versions.

## 5. Return the range to ordinary operation

1. Reconnect the target to whatever software the range normally uses.
2. Fire one sighter and confirm it is captured once.
3. Confirm the score, coordinates and sequence are correct.
4. Record on the checklist that the range was returned to ordinary operation,
   with the time.

---

## What rollback does NOT do

- It does not delete RC1 logs, journals, exports or support bundles.
- It does not modify the preserved evidence folder.
- It does not uninstall anything — RC1 is portable, so removing the folder is
  enough, and even that should wait until the evidence is safely copied.

## If rollback itself fails

Capture a support bundle from the **previous** build too, note the failure on
the checklist at **Severity 1**, and stop live testing. A range that cannot be
returned to ordinary operation is a blocking defect regardless of which build
caused it.
