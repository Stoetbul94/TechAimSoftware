## HISTORICAL-SCORE-001 — historical 10 m sessions rescore after SCORING-CAL-001

**STATUS: ACCEPTED FOR RC3.**

A saved `.tch` stores `x_data`, `y_data`, `time` and `time_stamp` and **no
score**, so a reopened or resumed qualification is rescored from coordinates. A
10 m session saved before SCORING-CAL-001 therefore reads lower — correctly —
when reopened after it. Accepted for RC3 because the package contains **no
historical user sessions**, SETA receives a clean first-run state, the new
calculation is the corrected ISSF calibre, and no migration will be invented
immediately before an external evaluation.

**Future v1.0 consideration (NOT implemented now).** Evaluate whether completed
sessions should persist the scoring-engine / ruleset version and/or the final
authoritative shot scores, so historical results stay exactly reproducible
across a scoring correction.

## Source-leakage audit

**`release/` is the development build tree and must never be shipped as-is.**
963 files, including 116 `.o`, 40 generated `.cpp` (among them `qrc_qml.cpp`,
which contains every QML file as embedded byte arrays), 1 `.h`,
`object_script.TechAim.Release`, Makefiles, **67 `.tch` development sessions**,
9 logs and 11 report PDFs.

The existing packaging script `tools/release/build-rc1-package.ps1` does **not**
copy that tree. It is a strict **allow-list**: `TechAim.exe`, a freshly written
`config.ini`, a fixed list of release documents, `LICENSE` /
`THIRD-PARTY-NOTICES`, `Make-SupportBundle.ps1`, the `.qm` translations, and the
Qt runtime resolved by `windeployqt`. Nothing source-like is enumerated, so no
`.cpp/.h/.pro/.pri`, tests, emulator source, Git metadata, Claude files,
project memory, Python or build scripts can reach the package by construction.

## QML exposure

- **No loose application `.qml` ships.** `qml.qrc` compiles **80** QML files
  into the binary and `main.cpp` loads `qrc:/main.qml`. The only `.qml`/`qmldir`
  files beside the executable belong to Qt's own modules, which the Qt runtime
  requires.
- No proprietary UI source file is directly readable as a file in the
  deployment.
- Nothing proprietary needs to stay external at runtime.
- **Stated honestly:** qrc data is embedded in the executable, so it is
  recoverable by a determined party. The requirement met here is *no source-code
  distribution* and a normal commercial compiled deployment — not
  unbreakability.

## Clean first-run

- Session, journal and log storage is
  `QStandardPaths::AppLocalDataLocation` (`src/reliability/storage/StoragePaths.cpp`)
  — a per-user `%LOCALAPPDATA%` path. An installer cannot and does not copy the
  developer's AppData.
- The packaging script writes a **fresh** `config.ini`
  (`app_mode=Live`, `developer_mode=0`) and explicitly does not copy the
  developer's, so no local mode, developer flag, remembered port or
  machine-specific value can leak.
- The 67 `.tch` sessions, logs and report PDFs live in `release/` and are not on
  the allow-list.
- Registry keys `HKCU\Software\{Tachus,Seta}\shootingApp` hold only
  `isEulaAccepted` and `loadFilePath` on this machine; they are per-user state,
  not package content.

## Legacy branding

Six legacy assets are still compiled into the executable through `images.qrc`:
`bg_tachus.png`, `total_score_block_tachus.png`, `total_score_block_tachus_new.png`,
`logo/tachus.png`, `logo/tachus_logo.png`, `End User Agreement Tachus-1.png`.

They are reachable only through `isDefaultIcon`, which is **hardcoded `false`**
in `main.qml`, so **none is rendered** — SETA cannot see them in the running
application. They are recoverable from the binary by extraction. Removing them
from `images.qrc` is a small, safe deployment-manifest change; it is **not done
here** because it touches the resource manifest and this pass is audit-only.

## Runtime dependencies

`windeployqt` (present at `C:/Qt/6.5.3/mingw_64/bin`) resolves the Qt runtime.
The script documents a known Qt 6.5.3 MinGW `windeployqt` failure and uses an
allow-list built from its own dependency report plus the QML module imports.
The application requires no Qt Creator, Qt SDK, MinGW, repository path or
developer environment variable.

## Installer workflow

`tools/release/build-rc1-package.ps1` produces a **ZIP** plus a SHA-256 — not a
single installer `.exe`. The gap to
`TechAim-0.9.0-RC3-SETA-Evaluation-Setup.exe` is one packaging step over the
same curated payload. No third-party packaging tool (Inno Setup, NSIS) is
installed on this machine and none was installed: that choice needs Arnold's
approval.
