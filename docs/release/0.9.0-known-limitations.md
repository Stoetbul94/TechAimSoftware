# Tech Aim 0.9.0 — known limitations

Applies to 0.9.0-RC1, RC2 and RC2a. Last reviewed 2026-08-03 at commit
`4151620`.

Every entry is something we know. If a limitation is not listed here, it is not
because it is denied — it is because it is not yet known.

---

## 1. Not for official competition results

**This is field-test software.** No score, ranking or report from any 0.9.0
release candidate may decide a competition outcome, a selection, or an athlete
classification.

---

## 2. Physical qualification is incomplete

**One 10 m Air Rifle Training workflow has been physically tested**, on one
machine, with one target.

Not physically qualified: 10 m Air Pistol, 50 m Rifle Prone, 50 m Rifle 3
Positions, all Finals disciplines, and every Training Lab programme other than
the one exercised.

Automated coverage is substantial (2293 reliability, 568 training, 235 3P
finals, 143 10 m finals checks, all passing) but automated tests are not
hardware qualification — see limitation 3.

## 3. SERIAL-AUTO-001 — automatic COM detection

**Status: fixed in code, AWAITING PHYSICAL RE-TEST. Not closed.**

RC2 failed to detect the target automatically at the range. The selector was
correct but was called *after* a speculative connection that silently reused the
stored port, so it never ran. RC2a restructures startup to decide first and
connect second, and adds regression tests 35–43 that pin the *order*.

The defect stays open until Test A of the physical checklist passes on real
hardware with Bluetooth enabled. Every automated COM test passed while the
physical path failed — that is precisely why code changes alone do not close it.

## 4. Shot display latency — under investigation

A noticeable delay was observed between a physical shot and the screen
responding. RC2a adds correlated timestamps across the whole pipeline so the
delay can be **located**. It does not change any timing.

Note that some of the observed delay may be intended behaviour: in a Training
visibility mode that hides impacts, the marker is deliberately not drawn.

## 5. Auto-zoom — unverified

Auto-zoom is enabled by default but is deliberately suppressed in Training
programmes when impacts are hidden — the athlete is meant not to see the shot.
The RC2 test was a Training programme, so the observation may be correct
behaviour rather than a defect.

Not "fixed", because the code path is not demonstrably failing and loosening the
gate would risk revealing impacts a programme is meant to withhold. Test D
settles it.

## 6. Clean-machine test — blocked

Never run on a machine that has not had Qt installed. Windows Sandbox and
Hyper-V are unavailable on the development machine's Windows edition (Home), and
no second machine or VM is available. An isolated-launch test was done instead
and passed, but it is weaker evidence. Checklist:
[Clean-Machine-Test.md](../deployment/Clean-Machine-Test.md).

## 7. No code signing

Binaries and packages are **unsigned**. Windows SmartScreen will warn when a
downloaded package is first run. Verify the SHA-256 instead — that is the actual
integrity check.

No Tech Aim artefact may be described as code-signed, and no claim may be made
about SmartScreen reputation.

## 8. No crash dumps

No crash handler is installed. A crash leaves only the Windows event log and
whatever the log file captured before the process died. Collect a support bundle
immediately after any crash.

## 9. LOG-001 — logs are written to the Windows TEMP folder

The operational log is `%TEMP%\tachus_log<timestamp>.log`, one file per launch.
The AppData `Logs` directory exists but nothing writes to it.

Consequences: Windows Disk Cleanup and Storage Sense can delete diagnostic
evidence, and log files accumulate (88 observed on one machine). **Collect
support bundles promptly.** The bundle collects both locations.

Recorded as a runtime defect, deliberately not fixed in the deployment-
preparation branch so the binary under physical test stays byte-identical.

## 10. CFG-001 — configuration is loaded by relative path

`config.ini` is resolved against the process working directory. Starting
`TechAim.exe` with a different working directory — for example a shortcut whose
"Start in" field is wrong — silently loads defaults instead.

Start the application from its own folder. Any future shortcut or installer
must set the working directory to the install folder.

## 11. No installer

The portable ZIP is the only supported deployment method. No installer exists
and none is built; the trade-offs are in
[Installer-Options.md](../deployment/Installer-Options.md).

## 12. PKG-002 — windeployqt fallback

`windeployqt` fails on the build machine with a platform-plugin error, so
packaging falls back to an explicit allow-list built from windeployqt's own
dependency report. Every RC so far used the fallback. The audit verifies every
shipped directory, but the underlying failure is undiagnosed.

## 13. 25 m Pistol disciplines are not implemented

Which events are in scope is still an open product decision.

## 14. 50 m Rifle 10-ring radius needs confirmation

`radOf10Ring = 5.2` in the scoring geometry needs either official rulebook
confirmation or physical calibration.

## 15. Licence-expiry check is disabled

Deliberately commented out. Re-enabling needs separate approval and a licence
test fixture.

## 16. Coach Report — COACH-001 remains open

Diagnostics were added; no eligibility or analytics rule was changed.

## 17. Training Lab evidence classification

Athlete-facing claims are classified as research-supported, reasoned product
rule, or awaiting validation, and enforced by an automated check (903 checks
passing). **Impact data cannot name a technical cause.** Recommendations
describe patterns and propose controlled tests; sight and technique decisions
belong to the athlete and coach. There is no coach approval of these programmes.

## 18. The vendored Modbus window is unreachable

The application embeds a vendored QModMaster fork whose window is never shown.
Its dialogs and settings cannot be reached, by design.

---

## Not limitations — things that are working

Recorded so they are not re-litigated:

- **Automatic paper feed** passed its first physical test in RC2 and is
  unchanged in RC2a.
- **Upgrade, rollback and removal preserve user data** — 35 checks, 0 failures,
  with the data root reconciling exactly.
- **Bluetooth ports are never opened**, being rejected on metadata alone.
