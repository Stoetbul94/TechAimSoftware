# Acquisition gate results — 2026-08-10

All four gates run against the **real application** over Modbus TCP, driving the
production acquisition path. Discipline: **10 m Air Pistol** — a workflow that
had never been exercised, so these also confirm the shared engine behaves
identically outside Air Rifle.

Commit under test: `a380b91`.

## Classification

These gates were run against the real application driving its production
acquisition path, but the target was the **emulator**, not physical hardware.
The distinction is preserved deliberately — implementation coverage is not
physical validation.

SYNC-001 is **not** a hardware-found defect. It was introduced by the
`b810323` safeguard and caught by the deterministic emulator scenario before it
reached a range or an external evaluator. Recording it otherwise would credit
hardware testing with a catch it did not make.

**RESTART-001**
- **OPEN — SEVERITY 1**
- PHYSICAL SHOT LOSS OBSERVED ONCE
- ROOT TRIGGER NOT ESTABLISHED

**COUNTER-ANOMALY SILENT-FAILURE SAFEGUARD**
- **PROVEN AGAINST REAL APPLICATION + EMULATOR**

The architecture now guarantees that an unsafe counter anomaly cannot silently
leave the application indefinitely ignoring shots. This is a separate and
weaker claim than "RESTART-001 is fixed", and the two must not be conflated:
the trigger is still unknown, the failure mode is no longer silent.

## 1. Synchronization — baseline 0, hardware 2

```
04:03:31.340  SYNCHRONIZED baseline 0 -> 2 (adopted from target; 2 pre-existing
              count(s) ignored, NOT replayed as shots)
04:03:31.347  resetShootinCount READBACK rc=2 hwCounter=2
04:03:31.359  SYNCHRONIZED baseline=2 (already in agreement)
```

Side effects: **0 fetches, 0 decoded, 0 ShotAccepted, 0 scores, 0 feeds.**

Counting the side effects is the point. `b810323` logged "NOT replayed as shots"
and then replayed them — the claim is worthless without the counts.

`hwCounter=2` is also the first time the FALSE-SHOT-001 readback has ever seen a
non-zero value. Its fault condition is finally exercised.

## 2. NewShots — hardware 2 → 3

```
04:08:31.048  ACCEPT raw=3 baseline=2 delta=1
04:08:31.051  Collecting data for shoots from 2 to 3     <- SLOT 3 ONLY
04:08:31.062  original X 0.3 ... for shoot 3
04:08:31.163  physical shot accepted: seq 3
04:08:32.400  paper feed completed: shot 3
04:09:11.552  poll=3100 rawCounter=3 baseline=3 delta=0  <- no duplicate
```

1 fetch, 1 decoded, 1 ShotAccepted, 1 marker, 1 feed. The fetch range is
`2 to 3` — slot 3 alone, not 1–3. That was the specific residual risk after
SYNC-001 and it did not occur.

## 3. Active gap — baseline 2, hardware jumps to 4

```
04:15:40.084  ACQUISITION_FAULT counter JUMPED by 2 (target 4, baseline 2)
              - shots may have been missed - acquisition STOPPED,
                operator warned, session preserved
04:17:07.790  poll=2990 rawCounter=4 baseline=2 delta=2 [heartbeat]
```

0 fabricated shots, 0 fetches, 0 feeds. Latched ~90 s / ~900 polls, reported
once, no spam. **The baseline was NOT adopted** — absorbing the gap would have
hidden the missing shots.

RC2f met this exact condition and did nothing at all: no log, no state change,
shots ignored indefinitely.

## 4. Backwards counter — baseline 2, hardware drops to 1

```
04:22:31.010  ACQUISITION_FAULT counter went BACKWARDS (target 1 is below
              baseline 2) - acquisition STOPPED, operator warned,
              session preserved
04:23:03.829  poll=2490 rawCounter=1 baseline=2 delta=-1 [heartbeat]
```

0 fetches, 0 decoded, 0 accepted, 0 feeds. Latched, no spam.

This was the likeliest to slip through: `newShotsCount > m_currentShootsCount`
is false for a backwards counter, so a naive path falls into silent rejection —
the original RESTART-001 deadlock.

## What is proven, and what is not

**PROVEN:** no counter condition produces silent indefinite shot loss. Every
outcome is a correct shot or a named, latched, diagnosable fault.

**NOT PROVEN — and this is a release blocker.** None of these states is visible
to the operator. `targetStateChanged` emits `TARGET DISCONNECTED`,
`RECONNECTING`, `TARGET CONNECTED` and `ACQUISITION FAULT`, but **no QML
consumes it**. During gates 3 and 4 the shooting screen continued to look
healthy while acquisition was stopped. An athlete would fire into a target
recording nothing.

**RESTART-001 remains OPEN.** Its root trigger is still unknown. What has
changed is that its failure mode can no longer cause silent loss.

## Remaining before any candidate

2. Automated Tests A–G in the harness, so these gates run without hardware or
