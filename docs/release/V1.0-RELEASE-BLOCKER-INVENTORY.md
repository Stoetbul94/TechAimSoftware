### Found and fixed while closing G

**The journalled per-shot time was wrong.** The split was measured for the
screen and then measured *again* for the journal, after the clock anchor had
already advanced — so every persisted shot time was near zero, and every

### G — 10 m Air Rifle / Air Pistol Final report and PDF (F6) — **CLOSED**

**Was:** `Finals10mController` had no `buildReport()`, and `ReportWindow`'s
`finalsMode` tested only `shootingPage.isFinalsMatch` — the 3P flag. A 10 m
Final fell through to the Summary and Match tabs, whose own comment says they
"carry qualification assumptions that must never be fed finals data". *View
Report* on the completion card only redisplayed the completion card.

**Now:** closed in full — see the table above. Asserted by `tests/finals10m`
(229 checks) and `tests/qml` (440 checks), and shown by two rendered report
pages built from real controller output.

### F — FINALS-TCH-SIGHTER-001: explicit sighter/official persistence — **CLOSED**

**Verified in the field, 2026-08-29:** the 10 m Final `.tch` (and, it turns
out, the 3P qualification `.tch`) holds officials and sighters
undifferentiated. RC3C's `Match_25082026-210107.tch` has 29 rows for a 24-shot
Final; RC3F's qualification records hold 67/72/74 rows for a 60-shot course.

**Why it blocks:** G cannot be built correctly on top of it. A report that has
to *infer* "the first five were sighters" is a report that will eventually be
wrong. The persisted record must carry the role.

**Scope:** persist `shotRole` (SIGHTER/OFFICIAL) and `position` explicitly;
read older files safely without fabricating certainty for historical data.

**These two are one round.** F is the foundation; G is the deliverable.

## SHOULD FIX BEFORE V1.0 — ALL CLOSED

All four were presentation or command-text only, and all four are done: A, B
and C were fixed and re-verified green in this round's regression, and D was
closed by F, which is where it always belonged.

### A — UI-LASTSHOT-DWELL-001

Measured on three tablets: **1.63–2.03 s**, mean 1.84 s, from
`qml-marker-added` to the position change clearing the face. Incidental (paper
feed + a 500 ms poll), not designed. SEV-3, competition behaviour correct.

**Fix:** a 2.5 s presentation-only hold of the last marker and score.

### B — CRO-ORDER-001

`END OF PREPARATION AND SIGHTING...STOP` announced ~138 ms **after**
`MATCH FIRING...START` on all three tablets. Rule 6.11.1.1 j) → 6.11.1.2 a)
requires STOP, a pause, then MATCH FIRING. SEV-3, announcements only.

### C — CRO-REPEAT-002

`MATCH FIRING...START` announced again at each position change — three times
per session. The qualification has one match period and one such command.
SEV-3, announcements only.

### D — position-change sighters tagged `(counted)`

The backend tags 3P position-change sighters `(counted)` because the 3P
transition deliberately avoids `MODREADER.changeSighterMode()` (it races the
polling worker). Course interpretation is correct — officials come from
`globalMatchModel` — but forensic analysis has to split by position to get the
true count, which is how the RC3F audit had to be done.

**Fix:** make the role explicit in the event/session model. **This is the same
work as F** and should be done with it.

### H — 10 m Final reload consistency beyond the report

Covered once G and F land. Anything remaining after that is deferred.

### `.tch` does not carry the shot role

The authoritative journal always has; the `.tch` never did. A file reopened
through *Load saved session* therefore presents its shots as one
undifferentiated match. Changing the `.tch` schema is a persistence-format
change and is out of scope for a freeze. **ACCEPTED LIMITATION / POST-v1.0** —
see the report matrix, note ².

### Reopening a completed Final as a Final

At completion the result is viewable and exportable, and that is v1.0's
contract. Later, *Load saved session* restores a generic match record, not a
Final, so the Final's structure is not shown again. A historical
completed-result browser was never designed or promised, and the crash-recovery
path must not be repurposed as one. **ACCEPTED LIMITATION / POST-v1.0** — see
the report matrix, note ⁴.

### I / J — Open Practice and Training report/reload

To be **characterised** in this round (below), not redesigned. Any defect found
is triaged then; a wish for a prettier report is not a blocker.

collector needed fixing. It does not.* The one small improvement worth making
is naming the finals journal explicitly in `WHAT-WAS-COLLECTED.txt` so its
absence is obvious — **documentation-grade, not a blocker**.

### Generated-manual provenance

`tests/docs/check_generated_manuals.py` requires the build manifest's
`documentationSourceCommit` to equal current `HEAD`. The manuals were last
built at `488d506`, 57 commits ago, and the check has been red ever since —
**before this round, and not because of it**.

The gate is structurally unsatisfiable in a clean tree: building the manuals
produces a manifest naming the current HEAD, and committing that manifest moves
HEAD past it. It is documentation provenance, not scoring, acquisition, rules,
persistence or report correctness, so it does not meet the blocker standard.
**Recorded, not fixed for v1.0.** Closing it needs the check reworked to compare
against the manuals' own commit rather than HEAD.
