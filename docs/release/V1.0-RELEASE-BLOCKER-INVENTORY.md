## BLOCKER

### G — 10 m Air Rifle / Air Pistol Final report and PDF (F6)

**Verified 2026-08-30:** `Finals10mController` has **no `buildReport()`**
(`grep` returns only `Finals3PController.h:130`), and
`ReportWindow.qml:21`'s `finalsMode` tests **only `shootingPage.isFinalsMatch`**
— the 3P flag. A 10 m Final therefore falls through to the Summary/Match tabs,
whose own comment three lines above says they "carry qualification assumptions
that must never be fed finals data."

**Why it blocks:** a competition mode that persists a session but cannot
produce a correct report is not a finished product. Report correctness is
explicitly in the blocker standard.

**Scope:** `Finals10mController::buildReport()` returning an immutable derived
map (the `FinalsReportBuilder` pattern — every value derived in C++, QML only
formats); a 24-shot report view; `finalsMode` extended to either finals family;
PDF via the existing `createFinalsPdf()` path; round-trip tests.

**Estimate: its own round.** Attempting it alongside other work produces a
half-built report and a worse gate.

### F — FINALS-TCH-SIGHTER-001: explicit sighter/official persistence

**Verified in the field, 2026-08-29:** the 10 m Final `.tch` (and, it turns
out, the 3P qualification `.tch`) holds officials and sighters
undifferentiated. RC3C's `Match_25082026-210107.tch` has 29 rows for a 24-shot
Final; RC3F's qualification records hold 67/72/74 rows for a 60-shot course.

**Why it blocks:** G cannot be built correctly on top of it. A report that has
to *infer* "the first five were sighters" is a report that will eventually be
wrong. The persisted record must carry the role.

**Scope:** persist `shotRole` (SIGHTER/OFFICIAL) and `position` explicitly;
read older files safely without fabricating certainty for historical data.

**These two are one round.** F is the foundation; G is the deliverable.

## SHOULD FIX BEFORE V1.0

Bounded, evidenced, and cheap. All four are presentation or command-text only.

### A — UI-LASTSHOT-DWELL-001

Measured on three tablets: **1.63–2.03 s**, mean 1.84 s, from
`qml-marker-added` to the position change clearing the face. Incidental (paper
feed + a 500 ms poll), not designed. SEV-3, competition behaviour correct.

**Fix:** a 2.5 s presentation-only hold of the last marker and score.

### B — CRO-ORDER-001

`END OF PREPARATION AND SIGHTING...STOP` announced ~138 ms **after**
`MATCH FIRING...START` on all three tablets. Rule 6.11.1.1 j) → 6.11.1.2 a)
requires STOP, a pause, then MATCH FIRING. SEV-3, announcements only.

### C — CRO-REPEAT-002

`MATCH FIRING...START` announced again at each position change — three times
per session. The qualification has one match period and one such command.
SEV-3, announcements only.

### D — position-change sighters tagged `(counted)`

The backend tags 3P position-change sighters `(counted)` because the 3P
transition deliberately avoids `MODREADER.changeSighterMode()` (it races the
polling worker). Course interpretation is correct — officials come from
`globalMatchModel` — but forensic analysis has to split by position to get the
true count, which is how the RC3F audit had to be done.

**Fix:** make the role explicit in the event/session model. **This is the same
work as F** and should be done with it.

## ALREADY CLOSED — verified, not assumed

### E — support-bundle collection of finals journals

**This is already implemented.** `Make-SupportBundle.ps1` collects, by default
(`-RecentHours 12`, no `SessionId` needed):

```powershell
Get-ChildItem (Join-Path $appData 'Sessions') -Recurse -File -Filter '*.jsonl'
```

and the finals journal is `Sessions/Current/finals_session.jsonl`
(`StoragePaths.cpp:79`), which that search matches.

**The RC3F evidence lacked the journals because `Collect-Logs.cmd` was never
run** — none of the three folders contains a support bundle, only the shipped
script. The gap was procedural, not a code defect.

*Correction to the RC3F audit's "Remaining open items", which implied the
collector needed fixing. It does not.* The one small improvement worth making
is naming the finals journal explicitly in `WHAT-WAS-COLLECTED.txt` so its
absence is obvious — **documentation-grade, not a blocker**.
