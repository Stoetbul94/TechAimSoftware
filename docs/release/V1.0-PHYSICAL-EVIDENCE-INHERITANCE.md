## The condition that would void this inheritance

**If acquisition, scoring, Modbus, counter reconciliation, paper feed,
authoritative competition timing, or the 3P state machines are modified, the
RC3F evidence no longer applies** and a new physical test is required before
any physical claim may be repeated.

As of this document none of those has been touched since RC3F. Verified per
commit: the post-RC3F diffs are confined to `CenterPane.qml`,
`ShootingPage.qml`, `src/finals10m/`, `tests/`, `tools/release/` and `docs/`.

## How to state this honestly

Correct:

- **CORE PHYSICAL ACQUISITION: PASS** via RC3F field evidence
- **3P PHYSICAL: PASS** (qualification), **completion PASS** (Final)
- **POST-RC3F UI/CRO CLOSE-OUT: AUTOMATED REGRESSION PASS**
- **10 m FINAL PERSISTENCE: AUTOMATED ROUND-TRIP PASS**
- **WINDOWS V1.0: ACCEPTED WITHOUT ADDITIONAL LIVE RETEST**

Incorrect, and must not be written anywhere:

- ~~"all v1.0 features physically tested"~~
- ~~"the 10 m Final report was physically tested"~~ — its underlying shots come
  from a physical baseline; **the report path itself is replay-validated**
- ~~"the 3P Final state flow is field-verified"~~ — the Final *completed* in the
  field; its internal stage flow was not captured, because the journals were
  not collected
