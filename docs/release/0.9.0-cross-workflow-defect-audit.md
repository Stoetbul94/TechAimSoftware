# Tech Aim — cross-workflow defect audit

Required before RC3. Applies the global fix policy **retroactively** to every
defect confirmed during the 2026-08-08 physical testing.

Audited at commit `af5b730` on `feature/rc2e-latency-and-reset`.

> **The objective is not "10 m Air Rifle works". It is "the shared single-target
> engine is correct, and each discipline is a validated consumer of it".**

---

## Status vocabulary

**APPLIES** · **DOES NOT APPLY** · **AUTOMATED PASS** · **EMULATOR PASS** ·
**PHYSICAL PASS** · **PHYSICAL PENDING**

A fix implemented in a shared layer **applies** to every consumer. It is
**not** physically validated in a workflow unless that workflow was actually
tested. Only 10 m Air Rifle Training/Practice has been physically exercised.

---

## The shared engine, as it actually exists

| Layer | Owner | Consumers |
|---|---|---|
| Serial discovery / connection | `TachusWidget::connectedModbus()`, `TargetDeviceSelector` | every Live workflow — `MODREADER` is the only hardware bridge |
| Hardware counter authority / baseline | `TachusWidget::resetShootinCount()` | every Live workflow |
| Shot acquisition + decode | `TachusWidget::on_pushButton_2_clicked()` → `checkForNewShots()` | every Live workflow |
| Accepted-shot → paper feed | `PaperFeedCoordinator` (hooked at the C++ acceptance site) | every Live workflow |
| Shot display / scoring | `CenterPane.qml` | `ShootingPage.qml`, `RightPanel.qml` |
| Session persistence / recovery | `SessionStore`, `SessionReducer`, `RecoveryCoordinator` | all disciplines |

**Verified by inspection:** the QML files consuming shot counts directly are
`CenterPane`, `ShootingPage`, `SeriesComponent`, `MatchReportInfo`,
`SummaryReportView`. `CenterPane` is referenced only by `ShootingPage` and
`RightPanel`.

**AUDIT-001 — RESOLVED.** `Finals3PController` and `Finals10mController` carry
their own shot-consuming logic and sit *above* the C++ acquisition and feed
layers, so they inherit those fixes. On the display side, `FinalsHud.qml` and
`Finals10mHud.qml` both reference the shooting page: the Finals interface is a
**HUD overlaid on the same shared shooting page**, not a separate shot display.
Finals therefore inherit the `CenterPane` fix as well.

**Consequence:** every fix in this audit reaches every discipline through a
shared layer. There is no discipline with a private acquisition, feed or
shot-display path.

## Defect matrix

### SERIAL-AUTO-001 — automatic COM detection

- **Symptom:** target not detected; manual COM entry required with Bluetooth present.
- **Root cause:** the selector ran *after* a speculative connect that let settings substitute the stored port.
- **Shared fix location:** `TachusWidget::connectedModbus()` — the single connection entry point.

| Workflow | Status |
|---|---|
| 10 m Air Rifle | APPLIES · **PHYSICAL PASS** |
| 10 m Air Pistol | APPLIES · PHYSICAL PENDING |
| Practice / Training | APPLIES · **PHYSICAL PASS** |
| Match | APPLIES · PHYSICAL PENDING |
| Finals (3P, 10 m) | APPLIES · PHYSICAL PENDING |
| Recovery | APPLIES · PHYSICAL PENDING |
| Automated | **AUTOMATED PASS** — tests 35–43 |
| Emulator | Partial — TCP path verified, RTU selection not emulated |

### FALSE-SHOT-001 — phantom / stale shot

- **Symptom:** a shot nobody fired, carrying the previous session's coordinates.
- **Root cause:** the app assumed the target's counter was 0 after a reset it never verified.
- **Shared fix location:** `TachusWidget::resetShootinCount()` — executes before any discipline-specific scoring or QML processing, so all Live workflows inherit it.

| Workflow | Status |
|---|---|
| All Live workflows | APPLIES (shared authority) · PHYSICAL PENDING |
| 10 m Air Rifle | APPLIES · **NOT REPRODUCED** in the RC2d run — the counter read 0, so the safety path never ran |
| Automated | None — the defect is in the Modbus path against firmware that ignored a reset it acknowledged |
| Emulator | **NOT YET PROVEN** — see AUDIT-002 |

> **AUDIT-002 — the fix's execution is in doubt.** During the Scenario B
> emulator run the emulator received **no write to register 8193**, although
> `resetShootinCount()` ran. The hardware reset *and* the baseline-adoption read
> share one `if (isAppDemoMode)` block, so neither executed. Whether the cause is
> the guard or a not-yet-ready connection has **not** been isolated.
>
> **This must be resolved before RC2e is packaged.** Shipping a fix that does
> not execute would carry a phantom-shot risk into the SETA build under the
> appearance of being fixed.

### PAPER-FEED-001 / 002 — suppressed feed after a numbering reset

- **Symptom:** the first counted shot after sighters did not advance the paper.
- **Root cause:** the duplicate-feed key was `sessionId#identity`; shot numbering restarts at 1 on a sighter/match swap, so the counted shot looked like the sighter.
- **Shared fix location:** `PaperFeedCoordinator` (kind in the identity) **plus** notification from `resetShootinCount()` — the one authority that clears the count.

| Workflow | Status |
|---|---|
| 10 m Air Rifle | APPLIES · **PHYSICAL PASS** (5/5 feeds, sighter→counted boundary) |
| 10 m Air Pistol | APPLIES · PHYSICAL PENDING |
| Practice / Training | APPLIES · **PHYSICAL PASS** |
| Match | APPLIES · PHYSICAL PENDING |
| Finals | APPLIES (feed hook is below the controllers) · PHYSICAL PENDING |
| Recovery | APPLIES — replay is checked **first**, before liveMode | PHYSICAL PENDING |
| Automated | **AUTOMATED PASS** — tests 20a–20d, verified to fail on the old key |
| Emulator | Not yet exercised |

**Policy compliance:** the workflow-specific notification previously added to
`changeSighterMode` was **removed**, not left alongside the central one. No
duplicate workaround remains.

### QML-SHOT-001 — diagnostics aborting shot processing

- **Symptom:** shot displayed but never committed; auto-zoom never ran.
- **Root cause:** a ReferenceError on the first statement of `triggerAutoZoom` propagated into the shot handler and skipped `backEndShootCount`, `updateSeriesScore` and `saveMatch`.
- **Fix location:** `CenterPane.qml` — shared by `ShootingPage` and `RightPanel`.

| Workflow | Status |
|---|---|
| Any workflow using `ShootingPage` / `CenterPane` | APPLIES · **PHYSICAL PASS** (10 m Air Rifle) |
| 10 m Air Pistol | APPLIES · PHYSICAL PENDING |
| Finals (3P, 10 m) | APPLIES — the Finals HUD overlays the shared shooting page (AUDIT-001 resolved) · PHYSICAL PENDING |
| Automated | **AUTOMATED PASS** — 23 checks, verified to fail on the defect |

### Duplicate-shot protection

- **Shared fix location:** the accepted-shot authority in the C++ acquisition path (`newShotsCount > m_currentShootsCount`), plus the coordinator's recent-identity set.
- **Policy check:** no page-level duplicate guard was added. `Finals3PController`, `Finals10mController`, `QualificationController`, `SessionReducer` and `SessionStore` contain duplicate/idempotency logic, but that is **session-event** deduplication, not physical-shot acceptance — a different concern at a different layer. **No consolidation required**; recorded so it is not mistaken for a duplicate workaround later.

### Reconnect

- **Shared fix location:** `TachusWidget` connection/acquisition layer; independent of which discipline page is open.
- **Status:** APPLIES to all workflows · **PHYSICAL PENDING for every workflow** — reconnect was never reached in any physical session.

### Recovery / replay

- **Shared fix location:** `PaperFeedCoordinator::onShotAccepted()` checks `replaying` **first**, before liveMode, target-connected or duplicate. Historical shots therefore cannot generate a feed.
- **Status:** APPLIES to all · **AUTOMATED PASS** (reliability replay tests) · PHYSICAL PENDING.

never physically validated:

- Restart and unfinished-session recovery
- Target power-cycle with a non-zero residual counter
- Consecutive sessions without restarting the application
