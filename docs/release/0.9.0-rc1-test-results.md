## 3. Deployment audit — PASS (76 / 0)

756 files. No source, no tests, no seeded or athlete session data, no `.git`,
no `.claude`, no build scripts, no object files, no keys, no passwords, no
developer configuration, no absolute developer paths, no Demo profile data.
Required runtime present, including the MinGW C++ runtime and the Qt Windows
platform plugin. Every top-level directory is documented in the manifest.

**Two audit checks were wrong on first run and were corrected, not relaxed:**
Qt's own QML modules legitimately ship `.qml` (only *Tech Aim* QML is
forbidden), and a bare "review" substring flagged Qt's
`CharacterPreviewBubble.qml` (the seed check is now scoped to athlete names and
data shapes).

**One real packaging defect was caught by it:** `Qt6OpenGLWidgets.dll` was
missing, and the portable package would not start without it.

## 4. Portable launch — PASS

Extracted the ZIP to a clean directory and launched with
`-UseNewEnvironment`, which resets to the machine environment. **The machine
PATH contains no Qt** (verified). The application started and stayed up.

**This is not the clean-machine test.** See §5.

## 5. Clean-machine test — NOT PERFORMED

**CLEAN-MACHINE TEST BLOCKED — PHYSICAL ENVIRONMENT REQUIRED.**

No second Windows machine without Qt development tools was available. The
portable launch in §4 is a strong indicator — the machine PATH has no Qt and
the package supplied its own runtime — but it ran on the development machine,
where a Qt installation still exists on disk and could in principle be reached
by some other mechanism.

The full 15-step clean-machine sequence (extract → launch → QML pages → home
screen → Live config → AppData → logs → athlete → session start → forced
termination → detection → recovery → new session → relaunch) **has not been
run** and must be before the weekend.

## 8. Support bundle — **SUPPORT BUNDLE TOOL — PASS, with one gap**

Run against the packaged RC1 folder with no `-SessionId`. Generated
`TechAim-Support-2026-07-30-212409.zip`, opened and inspected file by file.

**Contains** — RC version `0.9.0-RC1` · channel `Internal Field Test` · the
limitation line · executable path, file version and SHA-256 · Windows product,
version and architecture · machine name · sanitized configuration ·
target-communication summary · known-limitations document.

**Correctly excludes** — no password/token/secret-shaped assignment · no
seeded review athlete names · no `.jsonl` journals · no repository files · no
unrelated sessions. Session data appears **only** when `-SessionId` is passed,
which is opt-in by design.

**Gap: the Git commit is not captured automatically.** The bundle names the
version, channel and executable SHA-256, and the script tells the operator to
copy the commit from Settings → ABOUT / BUILD — but Part 4 asks for the commit
*in the bundle*. The executable SHA-256 does identify the exact binary, so the
information is recoverable, but it is not as convenient as it should be.

**Not fixed in RC1.** Changing the script changes the packaged ZIP and its
SHA-256, and the brief is explicit that RC1 is not rebuilt unless a
release-blocking defect is found. This is not release-blocking. **Recorded as
Severity 3 for the next build**, and the operator instruction covers it
meanwhile.

**Also untested: log collection.** `%LOCALAPPDATA%\TechAim\Logs` was empty, so
zero log files were gathered — correct behaviour with nothing to gather, but
the log-collection path itself is unexercised. **Run the tool once at the range
after a real session**, before it is needed in anger.
